# Deploying Archie

The backend runs on Railway, as project `archie` in environment `production`. Its services, Postgres,
volume and variables are declared in `.railway/railway.ts` (Railway Infrastructure as Code).

## How a change ships

- **App code:** merge to `main`, the branch the `archie` service watches (`source` in `.railway/railway.ts`).
  Railway waits for that commit's GitHub Actions checks (`checkSuites: true`), then builds the root
  `Dockerfile` and deploys it. The deploy goes live only after `/health` answers.
- **Infrastructure:** edit `.railway/railway.ts`, run `railway config plan` to see the diff against
  Railway, then `railway config apply`. Railway doesn't read `.railway/` during deploys, so an
  unapplied edit changes nothing. `npm install` at the repo root first, so the CLI can load the SDK.

## Not in code

- **Secrets and the owner's email.** The repo is public, so these are `preserve()` in
  `.railway/railway.ts` and their values live only in Railway:
  - `POSTGRES_PASSWORD` on `Postgres`, generated by Railway when the database was created.
  - `OWNER_EMAILS` on `archie`, the owner's Apple ID email (comma-separated list).
  - `ANTHROPIC_API_KEY` on `archie`, the key that pays for whitelisted users' summaries and primers. Set it once from
    the owner's local `.env` (`railway variable set --service archie ANTHROPIC_API_KEY=…`, without echoing the
    value); without it the pipeline's model steps fail.
- **Transcription, YouTube and newsletter settings** on `archie`, declared `preserve()` in `.railway/railway.ts`;
  set each with `railway variable set --service archie NAME=…` without echoing the value:
  - `GROQ_API_KEY` and `OPENAI_API_KEY`: podcast transcription (Groq first, OpenAI as the fallback).
  - `SUPADATA_API_KEY` (optional): YouTube captions. Without it YouTube links fail with "needs setup" on Railway.
  - `INGEST_SECRET`: the shared secret for `POST /ingest/email`; use the same value as the newsletter Worker's secret.
  - `INGEST_EMAIL_DOMAIN` and `INGEST_ALIASES`: the domain newsletter addresses live on and the fixed aliases
    (such as `news@`) that map to the owner.
- **ffmpeg.** The image now installs it (podcast audio is split with it); nothing to configure.
- **The newsletter Worker.** Deploy it from `workers/newsletter/README.md` only after the API is live with
  `INGEST_SECRET` set, then switch Email Routing to it.
- **The domain.** Railway's generated `*.up.railway.app` domains can't be declared.
  `archie-production-4856.up.railway.app` routes to port 8000 on `archie`, and the iOS release build
  bakes it in (`scripts/install_ios.sh`).

## Rebuilding from scratch

1. Create an empty project `archie`, then link this checkout to it: `railway link --project archie`.
2. `railway config apply` creates both services. Postgres must boot with the pgvector image from its
   first start, so let IaC create it rather than adding the stock Postgres first. Postgres refuses to
   initialize until it has a password, so set `POSTGRES_PASSWORD` on `Postgres` and `OWNER_EMAILS` and `ANTHROPIC_API_KEY` on
   `archie` right after (`railway variable set --service <name> KEY=value`). Both services then
   redeploy and come up.
3. Generate a domain on port 8000: `railway domain --service archie --port 8000`. If it changes,
   update the default in `scripts/install_ios.sh`.
4. Check that `curl https://<domain>/health` returns `{"ok":true,"database":true}`, and that
   `curl -X POST https://<domain>/test/session` returns 404.
